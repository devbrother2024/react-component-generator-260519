# TDD Rule

> ⚠️ **이 규칙은 Rigid — 상황에 맞게 변형하지 마라**  
> `.claude/rules/` 내 다른 rules 파일에 상충 규칙이 있으면 그것을 우선한다. 이 파일은 기본값(fallback)이다.

## 적용 기준

### ✅ TDD 반드시 적용 대상

- **API 엔드포인트**: `server/index.ts`의 라우트 핸들러, 요청 검증, 응답 변환 로직
- **비즈니스 로직**: AI 생성 코드 전처리/후처리, 프롬프트 구성 로직, 컴포넌트 분석
- **유틸리티 함수**: 날짜 포맷, 텍스트 변환, 데이터 정규화, 에러 처리
- **커스텀 훅 로직**: `useComponentGenerator`, 상태 관리, side effect 통제 (렌더링 테스트는 불필요, 로직만)
- **버그 수정**: 재현 가능한 테스트 작성 → 실패 확인 → 수정 → 패스 → 리팩토링

### ❌ TDD 불필요 대상

- **TypeScript 타입 정의**: 컴파일러가 검증 (`.tsx` 파일의 타입 구문)
- **설정 파일**: `tsconfig.json`, `vite.config.ts`, `bun.toml` (일회성)
- **순수 UI 컴포넌트**: props를 받아 렌더링만 하는 경우 (단, 조건부 렌더링이나 계산 로직이 있으면 훅 테스트 필요)
- **CSS / 인라인 스타일**: 시각적 검증은 브라우저에서 (스타일 객체 값은 유틸 테스트로)
- **마이그레이션 스크립트**: 일회성 데이터 변환

## RED-GREEN-REFACTOR 사이클

### 1️⃣ RED: 실패하는 테스트 작성

**원칙:**
- **하나의 동작 = 하나의 테스트**
- **반드시 실행해서 실패 확인** — `bun test`로 빨간 화면 봐야 함
- **실패 이유가 "기능 미구현"이어야 함** — 문법 에러, import 누락은 테스트가 아님

**체크리스트:**
- [ ] 테스트가 명확한 Given-When-Then 구조를 따르는가?
- [ ] 기대값(expected)을 테스트에 먼저 정의했는가?
- [ ] 실행하면 AssertionError가 나타나는가?

### 2️⃣ GREEN: 최소한의 코드만 작성

**원칙:**
- **YAGNI**: 테스트를 통과하는 데 필요한 코드만
- **모든 테스트(신규 + 기존) 패스 확인** — `bun test` 전체 스위트 green
- **하드코딩 허용** (리팩토링 단계에서 제거)

**체크리스트:**
- [ ] 코드가 최소한인가?
- [ ] 신규 + 기존 테스트 모두 패스하는가?
- [ ] 타입 에러가 없는가?

### 3️⃣ REFACTOR: 중복 제거 & 품질 향상

**원칙:**
- **GREEN 유지**: 모든 테스트는 계속 패스해야 함
- **새로운 동작 추가 금지**
- **허용 개선**: 중복 제거(DRY), 변수/함수명 명확화, 헬퍼 추출

**체크리스트:**
- [ ] 테스트가 여전히 모두 패스하는가?
- [ ] 새로운 동작을 추가하지 않았는가?

### 4️⃣ 반복

다음 동작에 대해 RED 단계로 돌아간다.

## 삭제 강제 규칙

- 테스트 전에 프로덕션 코드를 먼저 작성했다면 **모두 삭제하고 RED부터 재시작**
- "참고용"으로 남기는 것도 금지
- "나중에 테스트 추가" = 즉시 삭제

## 변명 차단표

| 변명 | 반론 | 대응 |
|------|------|------|
| "너무 단순해서 테스트 불필요" | 단순할수록 테스트 작성이 빠르다. 비용 과대평가 중. | RED → GREEN (2분 이내) |
| "나중에 테스트 추가하겠다" | "나중에"는 영구 연기됨. 지금 RED 작성. | 즉시 중단 → 테스트 먼저 |
| "시간이 없다" | 버그 수정 시간 vs 테스트 시간 비교하면 TDD가 빠름. | 1개 동작 = 1개 RED (3~5분) |
| "삭제하면 낭비" | 테스트 없는 코드가 이미 낭비. | 삭제 후 RED 작성 |
| "프로토타입이다" | 프로토타입도 유지보수된다. | 탐색 끝 → 즉시 RED로 전환 |
| "복잡하니까 나중에" | 복잡할수록 테스트가 더 필요. 작게 쪼개기. | 작은 RED부터 시작 |
